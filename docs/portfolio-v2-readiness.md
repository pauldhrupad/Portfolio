# Portfolio 2.0 readiness review

Reviewed 5 November 2026 on `feat/portfolio-v2-redesign`, against `main` at `b234295`. **Ready for draft review.** This review does not authorize a merge or production deployment. The production gates below still need approval and verification in the actual hosting environment.

## What ships

- The Next.js App Router architecture remains intact. The shared design system provides graphite and off-white themes, cobalt accents, Geist typography, a floating responsive header, keyboard focus styles and a downloadable résumé.
- Hero and About present the developer's positioning, a CSS/SVG architecture illustration and the existing factual background. Motion remains optional and respects the user's reduced-motion setting.
- The homepage has exactly three visible project cards. Verified project data drives the card copy, case-study sections, links, screenshot captions and sitemap. Authentic screenshots replace the old canvas, with no WebGL requirement.
- The skills bento grid links eight categories to project examples. The compact timeline, academic cards, creative credential and three repository cards retain the supplied facts. Unverified EduNextG details remain hidden.
- Contact includes direct email, copying, labeled validation, error recovery and honest acceptance feedback. The footer has compact branding, résumé and social links, section navigation and back-to-top. The optional command palette remains omitted.

Verification used Node.js 24.21.0, npm 11.19.0, a local production server and isolated Chromium sessions. The first smoke run's same-origin failure was fixed and rerun. An initial browser assertion raced the native dialog close event; waiting for the completed close and focus restoration resolved the harness failure. npm's upgrade left cleanup warnings for old Windows native binaries held by the open development server; the clean verification copy avoids those files.

A server-rendering self-check with omitted media confirmed the preview renders its visible illustration label and feature text without a broken image or a fixed screenshot height.

The tracked/history scan found no matches for the checked Resend, GitHub, cloud key, private-key or credential-URL patterns. `.env.example` remains the only tracked environment file and contains placeholders. Client bundles contain no Resend configuration identifiers. Production test logs did not expose private data. External links use HTTPS and opener isolation. JSON-LD escapes `<`; the theme bootstrap is a constant script. No untrusted remote HTML is rendered. These are scoped checks, not a guarantee against every secret format or vulnerability.

## Accessibility results

The browser audit checks [WCAG 2.2 AA](https://www.w3.org/TR/WCAG22/) principles: visible focus, bypass navigation, logical heading order, labeled fields, descriptive image alternatives, keyboard and touch controls, focus restoration and reduced motion. Eighteen whole-page axe scans found no violations across homepage/case-study desktop and mobile states and mobile 404s in both themes. Four additional Contact/footer scans found none in idle desktop and mobile validation states. Controls checked in the responsive matrix were at least 44 px high. The native mobile dialog enters the close control, keeps focus inside, closes with Escape and restores focus. Status and error announcements were checked structurally and with UI state changes; real assistive-technology sessions were not run.

## Performance measurements

Lighthouse 13.6.0, local production Chrome, standard simulated mobile or desktop preset, cold browser loads. Mobile home is the median of three runs; each case and desktop home is one run. These results describe the tested build and machine, not deployed field performance. KB below is transfer bytes divided by 1,000.

| Page | Preset | Performance | LCP | CLS | Total blocking time | App JavaScript |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Home | Mobile | 100 | 0.925 s | 0 | 61 ms | 200.1 KB |
| Home | Desktop | 100 | 0.249 s | 0 | 0 ms | 200.1 KB |
| GharKaBite | Mobile | 97 | 2.656 s | 0 | 21 ms | 152.7 KB |
| Co-Parenting | Mobile | 97 | 2.659 s | 0 | 46 ms | 152.7 KB |
| 4D Chess | Mobile | 97 | 2.673 s | 0 | 60 ms | 152.7 KB |

Lighthouse Accessibility, Best Practices and SEO scored 100 in these runs. Some back/forward cache diagnostics reported Chrome memory pressure, classified by Lighthouse as not actionable. The optimized case pages transfer about 24% less JavaScript than the first audit (200.0 KB → 152.7 KB). Mobile case LCP improved from 2.728–2.736 s but still exceeds the 2.5 s target. CLS meets 0.1 in the tested runs. INP was not measured; total blocking time is not a substitute for field INP. See [Core Web Vitals](https://web.dev/articles/vitals). Deferring Geist Mono preload worsened the case measurements and introduced small shifts, so both locally served fonts retain their preload behavior. No reliable pre-redesign Lighthouse baseline exists for an apples-to-apples comparison.

## Release gates still open

- Confirm the production branch and canonical environment value in Vercel. This review targets a draft PR only.
- Verify delivery with an approved inbox and configured Resend key/sender/recipient. Local runs use the direct-email fallback and simulated acceptance; no real email was sent. Acceptance is not inbox delivery.
- Validate the hosting proxy and production abuse controls. The limiter is intentionally process-local and can be bypassed across instances or spoofed forwarded headers if the proxy does not sanitize them.
- Review mobile case-study LCP on the actual preview and collect field INP/CLS/LCP after an approved release. Physical devices and screen readers still need manual checks. For a manual pass, use a narrow phone and desktop in both themes, navigate with Tab and Escape, test all three project pages and downloads, and check form feedback with a screen reader.
- Monitor the development-only audit advisory and plan a compatible ESLint major upgrade. The existing missing LinkedIn URL and unverified experience details remain hidden; chess still has no hosted demo.
